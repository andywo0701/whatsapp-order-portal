# ThreeGoodies 落單上載

受保護的上載入口。同事登入後可提交 WhatsApp 對話導出、圈選圖片、聯絡人截圖，或一份貨品清單，並下載已完成的落單 Excel。上載時不用再選這是新單還是舊單。

固定同事帳號只有這四位：

- Andy：Super Admin（超級管理員）。頁首仍會顯示這個角色
- Debbie、Taya、Katherine：Admin（管理員）。頁首仍會顯示這個角色
- 四位都可以做網站上的操作：為其他管理員設定密碼（這個路徑不能改自己的密碼）、軟刪除提交、確認、更正或刪除顧客，以及更正或刪除貨品（名稱、價錢、備註、尺碼、顏色和其他規格）。也可以在列表一次勾選多筆再批量刪除。四位都可以上載，以及查看、搜尋、下載已發布的清單

每個人都可以在登入後更改自己的密碼。密碼不會寫進這個倉庫，也不會顯示在頁面上。

第一次登入時，如果私人 dataset 裡還沒有該帳號的雜湊，可以用托管平台的環境變數做一次性引導。登入成功後會立刻把 PBKDF2 雜湊寫入 `users/accounts.json`，之後只認這份雜湊，不再使用環境變數裡的明文。

引導用環境變數（只在該帳號還沒有雜湊時使用）：

- `SITE_USERS`：多行 `帳號:密碼`
- `SITE_USERNAME` 與 `SITE_PASSWORD`
- `SITE_PASSWORD_ANDY`、`SITE_PASSWORD_DEBBIE`、`SITE_PASSWORD_TAYA`、`SITE_PASSWORD_KATHERINE`

其他環境變數：

- `SESSION_SECRET`
- `HTTPS_ONLY`（生產環境保持 `true`）
- `HF_TOKEN` 與 `INBOX_DATASET`（私人 Hugging Face dataset，保存上載檔、密碼雜湊、顧客名冊，以及貨品清單。免費 Web Service 的磁碟不會保留檔案）

可選，網站沒有它們也能啟動。之後在 Render 上設定，不要寫進 git：

- `SCAN_WEBHOOK_URL`：掃描程式的 HTTPS 網址，用來接收「立即掃描」
- `SCAN_WEBHOOK_KEY`：交給那個網址的 Bearer 金鑰

健康檢查路徑是 `/healthz`。不要把 `.env`、密碼、token、webhook 網址、webhook 金鑰或客人資料放進倉庫。

## 上載大小

單檔上限是 4GB，一次提交的總量也是 4GB。這涵蓋至少一個 500MB 的匯出，也涵蓋大約 3GB 的 WhatsApp 備份壓縮檔。

頁面上的提交不會把整個檔案放在一次請求裡。瀏覽器會按 2MB 一段送出，最多約 3 段同時傳送，每一段都要登入和原本的 CSRF。2MB 在大約每秒 50KB 的線上仍可在 100 秒內送完。畫面在傳送期間就會更新整份檔案已送出多少；一段若約 90 秒還沒完成，會停下來再試，仍然失敗就顯示錯誤，按鈕會回到可再按的狀態。再按提交時會略過伺服器已經收到的部分。每一段各自寫進一個暫存檔，完成時才按順序接成原本的檔案，不會把幾段同時寫進同一個檔，也不會把整個檔案讀進記憶體。接好之後沿用同一個收件匣：私人 dataset、`manifest.json`、上載用途和紀錄日期。

沒有完成、或超過 24 小時的分段暫存會清掉。較大的檔案在本機組成之後，會在背景繼續上傳到私人 dataset，避免一次請求超過托管平台的時限。較小的檔案仍在回應之前上傳。

直接把一個很大的檔案貼進一次表單 POST 時，超過 4GB 會被拒絕。同事平常使用的頁面會自動分段。

## 上載用途

上載表單預設是「自動分辨」。同事可以改選三個用途。WhatsApp 紀錄日期（不指定、單日或日期範圍）跟以前一樣，可選。

自動分辨只看檔名和副檔名，不打開檔案，也不從圖片讀取姓名、電話或價錢：

- `.zip`、`.txt`（對話導出）→ `orders`（落單資料）
- `.xlsx`、`.xls`、`.csv`、`.doc`、`.docx`，而且檔名含有貨品、商品、產品、價目、價錢、價格、`catalog`、`catalogue`、`product`、`price`、`pricelist` 或 `sku` → `catalog`（貨品清單）
- 同一筆裡只要有一個這樣的試算表或 Word，整筆就是貨品清單
- 其他檔名，包括相片，維持落單資料

同事點選的用途會蓋過自動分辨。點了「客戶資料」就一定是客戶資料，即使檔名像貨品清單。

- `orders`：落單資料。對話導出、落單圖片。沒有 `purpose` 欄位的舊提交也當作這一種。
- `customers`：客戶資料。WhatsApp 群組聯絡人截圖、聯絡人清單，或含有電話的對話。檔案只是存起來，狀態維持「待處理」，直到掃描程式處理完並發布名冊。
- `catalog`：貨品清單。Excel、Word，或貨品相片。檔案只是存起來。這個網站不會從檔案裡讀價錢；價錢要等掃描程式發布 `catalog/catalog.json`。

`manifest.json` 會寫入最後採用的 `purpose`（`orders`、`customers` 或 `catalog`），不會寫入 `auto`。近期列表和詳情頁會顯示「落單資料」、「客戶資料」或「貨品清單」。

客戶資料和貨品清單一樣遵守刪除規則：四位同事都可以軟刪除提交，確認句是「確定刪除此提交？」，檔案留在原處，預設列表不再顯示。未登入的人打不開刪除頁。

## 類型不再由同事選擇

上載表單沒有「類型」下拉，也不再預設「新單」。新提交的 `kind` 是「待判斷」。掃描程式之後自行比較上一張落單，判斷新單、已改或已取消。這個網站不會替它做這個判斷。

如果請求裡仍帶有舊表單用過的類型（新單、改單、取消、已改、已取消、聯絡人截圖、其他），會照原樣保存，方便舊的提交和測試。不認識的值會存成「待判斷」。

已經在 dataset 裡、帶有 `kind` 的舊提交會照原來的文字顯示。沒有 `kind` 的舊提交打開時顯示「待判斷」，檔案本身不會被改寫。

## 貨品清單

登入後的導覽和首頁都有「貨品清單」。四位同事都可以查看、搜尋名稱、價錢或備註，以及下載 `貨品清單.xlsx`。沒有清單時，頁面會請同事去上載貨品清單。未登入的人不能打開這些頁面。

清單欄位：

- 貨品名稱（必須是字串；沒有名稱的列會略過，不會編一個名字）
- 圖片（可選，只保存檔名。網址不會被抓取）
- 價錢（保留掃描程式看到的原文和貨幣；沒有就顯示「尚缺」）
- 規格選項（可選）：每一列可以有尺碼／規格、顏色、其他規格，以及這一項自己的價錢。沒有規格價錢就顯示「尚缺」，不會拿總價來充數
- 備註
- 來源：掃描發布，或同事在網站更正後的「人手輸入」
- 最後更新日期
- 來源提交編號

Andy、Debbie、Taya、Katherine 都可以更正或刪除清單上的一項，也可以在清單頁勾選多項再批量刪除。更正頁可以改名稱、價錢、備註，以及新增、修改或清除規格。確認句是「確定儲存此貨品？」，單筆刪除確認句是「確定刪除此貨品？」，批量刪除確認句是「確定刪除已選的 N 筆？」，而且都要通過原本的 CSRF。已有價錢留空不會被清掉；要拿掉某一項規格，必須勾選「清除此規格」。儲存後這項貨品的 `source` 是 `manual`（人手輸入），編號維持原來的 `p` 開頭編號。刪除的是清單上的列，不是把已上載的檔案清掉。沒有勾選就按批量刪除時，不會刪除任何東西，頁面會請先選擇。

規則：

- 不會發明或換算價錢。價錢如果不是字串（例如 JSON 數字），會忽略，不會改成另一種寫法。規格價錢也一樣。
- 已經知道的價錢不會被空白覆蓋。規格上已經知道的價錢也不會被空白覆蓋。
- 發布檔沒有帶 `options`（或同義的規格欄）時，不會清掉已經保存的規格和規格價錢。
- 來源是人手輸入的更正，不會被後來發布檔裡的空白格子清掉。發布檔寫明的新價錢仍會整段取代。
- 掃描程式沒有提到的貨品會保留。漏掉一項不會刪除它；刪除要由同事在網站上做。
- 已被刪除的編號或同一個名稱，不會因為再次發布而回來。

## 掃描程式如何發布貨品清單

掃描程式處理 `purpose` 為 `catalog` 的提交之後，把整份清單上傳到同一個私人 dataset 的 `catalog/catalog.json`。圖片可以另外放到 `catalog/images/檔名`。dataset 還沒有 `catalog/` 時，網站會顯示空的清單，其他頁面仍可使用。

可以用 Hugging Face dataset API 上傳，或在已設定 `HF_TOKEN`（或 `HF_WRITE_TOKEN`）和 `INBOX_DATASET` 的環境執行：

```python
from pathlib import Path
from sync_inbox import publish_catalog

publish_catalog(Path("catalog.json"))
```

`publish_catalog` 會拒絕不是字串的 `name`、`price`、`image`、`note`，以及規格裡的 `price`，避免把數字價錢上傳出去。

`catalog/catalog.json` 例子（請只用假資料，不要把真實價錢放進倉庫）：

```json
{
  "version": 1,
  "updated_at": "2026-11-14T10:00:00+08:00",
  "updated_by": "scanner",
  "products": [
    {
      "id": "p0000abcd",
      "name": "測試蘋果",
      "image": "apple.png",
      "price": "HK$00.00",
      "note": "",
      "source": "scanner",
      "options": [
        {"size": "大", "color": "", "other": "", "price": "HK$00.00"},
        {"size": "中", "color": "", "other": "", "price": ""},
        {"size": "", "color": "紅", "other": "", "price": ""}
      ],
      "updated_at": "2026-11-14T10:00:00+08:00",
      "submission_ids": ["20261114-100000-abc123"]
    }
  ]
}
```

- `id`：可選，`6` 到 `64` 個英數、`_` 或 `-`。沒有的話，網站會依貨品名稱編成穩定的 `p` 開頭編號，方便再次打開同一項。同事更正時不會改這個編號。
- `price` 和 `name` 必須是字串。空字串表示沒有價錢，不是「尚缺」這兩個字。JSON 數字會被忽略。
- `image`：可選檔名，例如 `apple.png`。網站會在 `catalog/images/` 和來源提交的檔案裡找這個名字，不會跟任何網址要圖片。可在頁面上顯示的是 jpg、jpeg、png、webp、gif。
- `source`：`scanner`（掃描發布）、`manual`（人手輸入），或留空。掃描程式不應把新讀到的貨品標成人手輸入。網站上的更正會寫成 `manual`。
- `options`：可選。每一項是 `size`（尺碼／規格）、`color`（顏色）、`other`（其他規格）和 `price`（這一項的價錢，字串，可留空）。也可以用 `variants` 或 `specs`。只想列出尺碼或顏色時，可以改用 `尺碼`／`sizes` 或 `顏色`／`colors` 的字串陣列，例如 `["大", "中", "細"]` 或 `["S", "M", "L"]`。同一列同時有尺碼和顏色時，表示這個組合。
- `submission_ids`：相關的貨品清單提交編號。詳情頁會在找得到檔案時顯示連結。

網站讀取時會跟已經保存的清單合併，而不是整份覆蓋：

- 發布檔沒有提到的貨品會保留。
- 發布的價錢是空白，或根本沒有這個欄位時，不會清掉清單上已有的價錢。規格價錢也一樣：空白的規格價錢，或整份發布沒有 `options`，都不會清掉已知道的規格價錢。
- 新的非空白價錢會整段取代，保留掃描程式寫下的字符，不會換算。
- 來源已是人手輸入的貨品，之後若發布檔用空白格子覆寫，不會清掉人手留下的價錢或規格。寫明的新價錢仍會整段取代。掃描程式不應把 `source` 標成 `manual`。
- 已在網站上刪除的 `id` 或同一個名稱不會因為再次發布而回來。
- 讀取失敗或 JSON 無法解析時，沿用本機最後一份成功保存的清單，不會改成空的。

同事更正或刪除貨品時，會先把 `catalog/catalog.json` 和 `catalog/catalog.xlsx` 一起提交到 dataset。批量刪除也是一次提交。每次儲存或發布都會重新產生這份 xlsx。上傳失敗時，本機清單維持原狀。下載的 Excel 是依合併後的清單現做的，價錢儲存格用文字格式，避免試算表改寫金額。

`貨品清單.xlsx` 的欄位是：貨品名稱、圖片、尺碼／規格、顏色、其他規格、價錢、備註、最後更新日期、來源提交。圖片欄會嵌入已經保存在 `catalog/images/` 或來源提交裡的相片檔；沒有相片，或只有一個網址時，圖片儲存格留空，不會跟網址抓圖，也不會做一張假圖。貨品列的價錢是總價，沒有就顯示「尚缺」。某一項規格自己有價錢時，會再加一列，把該尺碼、顏色或其他規格和那個價錢寫在價錢欄。JSON 裡沒有價錢仍是空字串。

## 立即掃描

首頁和每一筆「待處理」提交的詳情頁都有「立即掃描」。同事按下後是一次 POST，並使用原本的登入與 CSRF。

如果 `SCAN_WEBHOOK_URL` 和 `SCAN_WEBHOOK_KEY` 都有設定，而且網址是沒有帳號密碼的 `https://`，伺服器會送出：

```http
POST /你的路徑 HTTP/1.1
Host: 掃描程式的主機
Authorization: Bearer （SCAN_WEBHOOK_KEY，不會出現在頁面或紀錄）
Content-Type: application/json; charset=utf-8
Accept: application/json

{"action":"scan","source":"whatsapp-order-portal","requested_by":"Andy","submission_id":"可省略"}
```

`requested_by` 是登入的同事帳號。從某一筆待處理提交按下去時，才會帶 `submission_id`。伺服器等待最多 8 秒，不跟隨重新導向，避免把金鑰轉送到另一個網址。回應是 2xx 才算成功，頁面顯示「已發出掃描要求，做好會把 Excel 放回這裡。」

這兩個環境變數是可選的，沒有它們網站一樣可以啟動。沒有設定，或網址不是 https 時，頁面會說可以在 Grok Bot 對話裡請它掃描。暫時連絡不上時，會請同事稍後再試，或改在 Grok Bot 對話裡請它掃描。兩種情況都不會當掉，也不會把網址或金鑰寫進頁面。

每位同事每 60 秒最多按 3 次。超過會請稍候再按，而且不會再呼叫 webhook。

不要把真實的 webhook 網址或金鑰放進倉庫、測試，或頁面。Render 上之後再加這兩個變數即可，不需要新的服務。

## 顧客名冊

登入後的導覽和首頁都有「顧客名冊」。四位同事都可以查看、搜尋姓名或電話、用「全部 / 尚缺電話 / 待確認」篩選，以及下載 `顧客名冊.xlsx`。沒有名冊時，頁面會請同事去上載客戶資料。未登入的人不能打開這些頁面。

名冊欄位：

- 顧客姓名
- 電話（保留發布時的寫法；沒有電話就顯示「尚缺」）
- 號碼來源：對話、聯絡人截圖、尚缺。同事在本網站更正姓名或電話之後，來源會改成「人手輸入」，表示這是人手更正，不是從圖片讀取的
- 最後更新日期
- 狀態：正常或待確認
- 備註／待確認

Andy、Debbie、Taya、Katherine 都可以確認待確認的顧客、更正姓名或電話，或刪除名冊上的顧客，也可以在名冊頁勾選多位再批量刪除。確認句分別是「確定確認此顧客？」、「確定儲存此更正？」、「確定刪除此顧客？」和批量的「確定刪除已選的 N 筆？」，而且要通過原本的 CSRF。更正時必須填說明。每次確認、更正、刪除都會記下是誰、在什麼時候、改了什麼。沒有勾選就按批量刪除時，不會刪除任何顧客。

規則：

- 不會發明姓名或電話。電話如果不是字串（例如 JSON 數字），會忽略，不會改成另一種寫法。
- 已經知道的電話不會被空白覆蓋。
- 同一個姓名出現兩個不同電話時，狀態維持待確認，頁面會同時列出兩個號碼，不會自動選一個。

## 掃描程式如何發布名冊

網站的顧客名冊只讀私人 dataset 的 `customers/roster.json`。下載用的是同一個 dataset 的 `customers/roster.xlsx`。只把 `顧客名冊.xlsx` 放在某筆提交的 `inbox/{id}/results/` 不會更新這個列表；頁面會仍然顯示沒有顧客。

掃描程式每次更新顧客名冊，都要呼叫 `publish_roster`。它會先讀出現有的官方名冊，合併之後，用一次 commit 同時寫上 `customers/roster.json` 和 `customers/roster.xlsx`。上傳失敗時，原來的官方名冊維持不變，不會只換掉其中一個檔。dataset 還沒有 `customers/` 時，網站會顯示空的名冊，其他頁面仍可使用。

在已設定 `HF_TOKEN`（或 `HF_WRITE_TOKEN`）和 `INBOX_DATASET` 的環境執行：

```python
from pathlib import Path
from sync_inbox import publish_roster

publish_roster(Path("roster.json"))
```

`publish_roster` 接受掃描程式稍寬鬆的輸入：`status` 可以是 `need_info` 或 `待補資料`，寫進官方名冊時會變成 `pending`（待確認）。沒有 `id` 的顧客會編一個 `c` 開頭的編號。空白電話不會清掉已經知道的號碼。同一個姓名有不同電話時維持待確認。已經刪除的顧客不會被這次發布救回來。

`customers/roster.json` 例子（請只用假資料，不要把真實電話放進倉庫）：

```json
{
  "version": 1,
  "updated_at": "2026-11-11T18:00:00+08:00",
  "updated_by": "scanner",
  "customers": [
    {
      "id": "c0000abcd",
      "name": "測試顧客甲",
      "phone": "0000-0000",
      "phone_source": "contact_screenshot",
      "status": "pending",
      "note": "",
      "submission_ids": ["20261111-120000-abc123"]
    }
  ]
}
```

- `id`：可選，`6` 到 `64` 個英數、`_` 或 `-`。沒有的話，網站會依姓名併到現有顧客，或自己編一個。
- `phone_source`：`conversation`（對話）、`contact_screenshot`（聯絡人截圖）、`manual`（人手輸入）、或留空（尚缺）。也可以直接寫中文。掃描程式不應把新讀到的號碼標成人手輸入。
- `status`：`ok`（正常）或 `pending`（待確認）。掃描程式如果寫 `need_info` 或 `待補資料`，`publish_roster` 會存成 `pending`。同一個姓名有多於一個電話時，網站會改成待確認。
- `submission_ids`：相關的客戶資料提交編號。詳情頁會在找得到檔案時顯示連結。
- `phone` 和 `name` 必須是字串。空字串表示沒有，不是「尚缺」這兩個字。

網站讀取時會跟已經保存的名冊合併，而不是整份覆蓋：

- 發布檔沒有提到的顧客會保留。漏掉一個人不會刪除他；刪除要由同事在網站上做。
- 發布的電話是空白時，不會清掉名冊上已有的電話。
- 同一個姓名如果同時有兩個不同的非空白電話，兩個都保留，狀態是待確認，不會自動挑選。
- 已在網站上刪除的 `id` 不會因為再次發布而回來。同一個姓名加上同一組電話也不會回來。
- 讀取失敗或 JSON 無法解析時，沿用本機最後一份成功保存的名冊，不會改成空的。

同事的確認、更正和刪除會先把 `customers/roster.json` 和 `customers/roster.xlsx` 一起提交到 dataset。批量刪除也是一次提交。上傳失敗時，本機名冊維持原狀。下載的 Excel 是依合併後的名冊現做的，電話儲存格用文字格式，避免試算表改寫號碼。`xlsx` 裡沒有電話的儲存格會顯示「尚缺」；JSON 裡仍是空字串。

## WhatsApp 紀錄日期

上載時可以選擇這些紀錄屬於哪一天，或一段開始到結束的日期。日期是香港日曆日（`Asia/Hong_Kong`），可以留空。日期在 manifest 裡的寫法不變。

有選擇時，`manifest.json` 會多兩個欄位：

- `record_date_start`：`YYYY-MM-DD`
- `record_date_end`：`YYYY-MM-DD`

只選一天時，兩個欄位都是同一天。結束日期不可早於開始日期。留空時，這兩個欄位都不會寫入。舊的提交沒有這兩個欄位，列表和詳情頁仍可開啟，並顯示「未指定日期」。

上載頁日期旁邊的說明是：

> 可選，以香港日曆計算。選了單日或日期範圍時，掃描程式發布的落單 Excel 只會保留落單日期落在這段日子裡的列，範圍以外的舊紀錄不會留在這份下載。留空時，這份 Excel 可以包含截至今天的全部現有紀錄。

這是掃描程式的契約，網站不會另做一份落單 Excel：

- 同事選了單日，或選了開始與結束日期時，掃描程式發布的那份落單 Excel 只能包含「落單日期」落在該窗口內的列。窗口以外的舊紀錄不得留在這份下載。
- 日期留空時，manifest 仍不寫日期。該份 Excel 可以包含截至今天的全部現有紀錄。

## 落單 Excel

網站不產生顧客落單活頁簿，仍由掃描程式發布，並放回該筆提交的結果檔。顧客落單表至少要有這些欄：

- 落單日期
- 貨品名稱
- 尺碼／規格
- 顏色
- 單價

尺碼／規格可以是大、中、細，或 S、M、L，或其他同事寫下的規格。顏色和單價沒有就留空，不要編造，也不要換算單價。上載時若選了紀錄日期，這一表只保留落單日期落在該窗口內的列。提交詳情在結果還沒準備好時，也會提到尺碼／規格、顏色和單價這三欄。
